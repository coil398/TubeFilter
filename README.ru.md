# TubeFilter

[English](./README.md) · [日本語](./README.ja.md) · [Español](./README.es.md) · [Português](./README.pt.md) · [Deutsch](./README.de.md) · [Français](./README.fr.md) · [Русский](./README.ru.md) · [한국어](./README.ko.md) · [简体中文](./README.zh.md)

**TubeFilter** — это кросс-браузерное расширение на Manifest V3, которое наводит порядок в вашей ленте YouTube, фильтруя контент по заданным вами порогам количества просмотров и числа зрителей трансляции. Оно затемняет или скрывает видео с малым числом просмотров и трансляции с малым числом зрителей, а также может независимо удалять рекламные верхние баннеры, списки «Микс» и Shorts. Настройки находятся во всплывающем окне на React, применяются мгновенно к открытым вкладкам YouTube без перезагрузки, а интерфейс всплывающего окна доступен на **9 языках** (English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어, 简体中文) с режимом **Auto**, который следует за языком вашего браузера. Количество просмотров/зрителей разбирается с учётом локали для тех же **9 языков страниц YouTube**.

## Краткий обзор

TubeFilter скрывает или затемняет элементы ленты YouTube, которые не дотягивают до заданных вами порогов просмотров/зрителей, и может по требованию удалять баннеры, списки «Микс» и Shorts. Чтобы попробовать его за три шага:

1. `npm ci`
2. `npm run build` (Chrome) или `npm run build:firefox` (Firefox)
3. Загрузите распакованную сборку из `.output/chrome-mv3` (или `.output/firefox-mv3`) — см. [Установка](#installation-end-users).

Ваши настройки никогда не покидают браузер: TubeFilter запрашивает только доступ к `storage` и к хосту `youtube.com`, и вся конфигурация хранится в локальном хранилище браузера.

## Возможности

### Фильтр по количеству просмотров (обычные видео)

Обычное видео фильтруется, когда выполнены **все** следующие условия:

- Фильтр видео включён (`enableVideoFilter`).
- Количество просмотров удалось успешно разобрать с карточки.
- Разобранное количество просмотров **ниже** вашего порога `minViews`.

Если у видео нет распознаваемого количества просмотров, оно остаётся нетронутым. Ползунок **Min Views** во всплывающем окне управляет порогом и отключается, когда фильтр видео выключен.

### Фильтр трансляций (прямые эфиры)

Прямые эфиры оцениваются по **отдельному** порогу — числу одновременных зрителей, а не общему количеству просмотров. Трансляция фильтруется, когда фильтр трансляций включён (`enableLiveFilter`), число зрителей удалось разобрать, и это число **ниже** вашего порога `minConcurrent`. Статус трансляции определяется по DOM-бейджам «в эфире» или по тексту в строке количества просмотров, указывающему на трансляцию (см. [Как это работает](#live-detection)).

### Контентные фильтры (без порога)

Эти три фильтра — безусловные переключатели вкл/выкл, они полностью игнорируют количество просмотров:

| Фильтр | Настройка | Что удаляет |
|---|---|---|
| **Top Banner** | `enableBannerFilter` | Рекламные баннеры в шапке и баннеры с заявлениями/промо. Когда совпавший баннер находится внутри rich-секции, скрывается вся родительская секция. |
| **Mix Lists** | `enableMixFilter` | Автоматически создаваемые плейлисты «Микс» / радио. |
| **Shorts** | `enableShortsFilter` | Ссылки и полки Shorts. |

### Режимы фильтра: скрытие против прозрачности

Селектор **Filter Mode** определяет, как обрабатываются отфильтрованные видео/трансляции:

- **Hide** — задаёт `display: none`, полностью убирая элемент из виду.
- **Opacity** — задаёт `opacity: 0.1`, затемняя элемент до **10%** непрозрачности, но оставляя его видимым. Это значение по умолчанию.

> ℹ️ Фильтр Top Banner всегда скрывает баннеры (`display: none`) независимо от выбранного режима фильтра. Режим фильтра влияет только на видео и трансляции.

### Приоритет фильтров

Каждая карточка классифицируется один раз в фиксированном порядке if/else. Применяется правило только первой подходящей категории:

1. **Shorts** (наивысший приоритет)
2. **Списки «Микс»**
3. **Прямые эфиры**
4. **Обычные видео**

### Отключение авто-дубляжа (принудительно оригинальная аудиодорожка)

Автоматический дубляж YouTube заменяет аудио видео на дорожку, переведённую ИИ, исходя из языка вашего интерфейса, — так что английское видео по умолчанию проигрывается на японском, немецком и т. д. С функцией **Force Original Audio** (`forceOriginalAudio`, **включена по умолчанию**) TubeFilter определяет оригинальную аудиодорожку и автоматически переключает на неё плеер на каждом видео и Short, отменяя авто-дубляж.

- Работает на видео `/watch` и Shorts, повторно применяется при каждой внутренней навигации в приложении.
- Оригинальная дорожка определяется **независимо от языка** путём декодирования id аудиодорожки плеера (данные оригинальной дорожки содержат `original`; дублированные дорожки содержат `dubbed` / `dubbed-auto`).
- Реализовано через **скрипт в MAIN-мире**, внедряемый в страницу, — аудио-API плеера YouTube недоступно из изолированного мира контент-скрипта, — а настройка пробрасывается из хранилища расширения.
- Отключите её в любой момент во всплывающем окне, чтобы оставить дублированное аудио YouTube.

### Многоязычное определение количества просмотров

YouTube отображает количество просмотров и зрителей **очень по-разному в зависимости от языка страницы** — не только переведёнными словами, но и разными десятичными разделителями и разделителями тысяч, а также единицами сокращений. Одно и то же количество ~1,7 миллиарда выглядит как:

| Язык | Строка YouTube |
|---|---|
| English | `1.7B` |
| Deutsch | `1,7 Mrd.` |
| 日本語 | `17億` |
| Русский | `1,7 млрд` |
| 简体中文 | `17亿` |

Контент-скрипт автоматически определяет **язык страницы YouTube** (`document.documentElement.lang`) и разбирает количества с правильным десятичным разделителем, разделителем тысяч и единицами сокращений для этой локали. Это важно, потому что предыдущий парсер предполагал формат в английском стиле и **неправильно читал локали с десятичной запятой** (`de` / `fr` / `ru` / `pt`) — например, читал `1,7 Mrd.` как `1` или `17` вместо `1 700 000 000`. Корректный для локали разбор поддерживается для **9 языков** (см. [Интернационализация](#internationalization)); неизвестные языки страниц используют запасной либеральный универсальный парсер.

### Языки (интерфейс всплывающего окна)

Интерфейс всплывающего окна предлагается на **9 языках** — English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어, 简体中文 — плюс режим **Auto (`auto`, по умолчанию)**, который следует за языком интерфейса браузера (`navigator.language`, сопоставленным с ближайшей поддерживаемой локалью, с возвратом к английскому при отсутствии). Выпадающий список в заголовке всплывающего окна переключает между ними.

## Использование

Откройте всплывающее окно расширения, чтобы настроить фильтрацию. Изменения сохраняются немедленно и применяются вживую к любой открытой вкладке YouTube — перезагрузка не требуется.

### Справочник по настройкам

| Настройка | Чем управляет | Диапазон / шаг | По умолчанию | JA label | EN label |
|---|---|---|---|---|---|
| `minViews` | Минимальное количество просмотров, ниже которого обычные видео фильтруются | диапазон `0`–`100000`, шаг `1000` | `1000` | 最低再生回数 | Min Views |
| `minConcurrent` | Минимальное число одновременных зрителей, ниже которого фильтруются трансляции | диапазон `0`–`5000`, шаг `50` | `50` | 最低同時接続数 (ライブ) | Min Concurrent (Live) |
| `filterMode` | Как обрабатываются отфильтрованные видео/трансляции (`hide` / `opacity`) | селектор из двух кнопок | `opacity` | フィルタリングモード | Filter Mode |
| `enableVideoFilter` | Включить/отключить фильтр по количеству просмотров (также включает/отключает ползунок Min Views) | переключатель вкл/выкл | `true` | 動画フィルタ有効 | Enable Video Filter |
| `enableLiveFilter` | Включить/отключить фильтр трансляций (также включает/отключает ползунок Min Concurrent) | переключатель вкл/выкл | `true` | ライブフィルタ有効 | Enable Live Filter |
| `enableBannerFilter` | Скрывать рекламные верхние баннеры | переключатель вкл/выкл | `true` | トップバナー非表示 | Hide Top Banner |
| `enableMixFilter` | Скрывать списки «Микс» | переключатель вкл/выкл | `true` | ミックスリスト非表示 | Hide Mix Lists |
| `enableShortsFilter` | Скрывать Shorts | переключатель вкл/выкл | `true` | ショート動画非表示 | Hide Shorts |
| `forceOriginalAudio` | Принудительно использовать оригинальную аудиодорожку (отмена авто-дубляжа) на страницах просмотра и в Shorts | переключатель вкл/выкл | `true` | 元の音声に固定 | Force Original Audio |
| `language` | Язык интерфейса всплывающего окна: `auto` + 9 локалей (`en`/`ja`/`es`/`pt`/`de`/`fr`/`ru`/`ko`/`zh`); **Auto** следует за языком интерфейса браузера (`navigator.language`) | выпадающий селектор | `auto` | Language | 言語 |

Оба ползунка показывают своё значение с разделителями тысяч через `toLocaleString()`. Под ползунком Min Concurrent расположена вспомогательная подсказка:

- JA: 視聴者数が少ないライブ配信はフィルタリングされます。
- EN: Live streams with fewer viewers will be filtered.

### Селектор режима фильтра

Элемент управления из двух кнопок. **Hide** задаёт `filterMode = 'hide'`; **Opacity** задаёт `filterMode = 'opacity'`. Активный режим подсвечивается. Подписи локализованы — JA: 非表示 / 薄く表示, EN: Hide / Opacity.

### Селектор языка

Выпадающий список в заголовке всплывающего окна задаёт `language` в значение `auto` или одну из 9 локалей (`en`/`ja`/`es`/`pt`/`de`/`fr`/`ru`/`ko`/`zh`). **Auto** (по умолчанию) определяет действующий язык интерфейса из `navigator.language`, сопоставляя его с ближайшей поддерживаемой локалью и возвращаясь к английскому при отсутствии. Выбор конкретного языка закрепляет интерфейс на нём независимо от настройки браузера.

## Как это работает

### Контент-скрипт

- **Совпадение и тайминг** — соответствует `https://www.youtube.com/*` и запускается на `run_at: document_end`.
- **Определение языка страницы** — на каждом проходе он читает `document.documentElement.lang` (с возвратом к `navigator.language`, затем `'en'`) и использует его для выбора корректного для локали парсера количества просмотров (см. [Интернационализация](#internationalization)).
- **Цели** — сканирует 7 селекторов видео, охватывающих Главную (`ytd-rich-item-renderer`), Поиск (`ytd-video-renderer`), Боковую панель (`ytd-compact-video-renderer`), Канал (`ytd-grid-video-renderer`), списки «Микс» (`ytd-radio-renderer`), отдельные Shorts (`ytd-reel-item-renderer`) и полку Shorts (`ytd-rich-shelf-renderer`); плюс 9 селекторов баннеров (`#masthead-ad`, `#big-yoodle`, `ytd-statement-banner-renderer`, `ytd-banner-promo-renderer`, `ytd-ad-slot-renderer`, `ytd-in-feed-ad-layout-renderer` и несколько вариантов `ytd-rich-section-renderer > #content > …`).
- **Обработка динамической ленты** — `MutationObserver` наблюдает за `document.body` с `{ childList: true, subtree: true }`. Когда добавляются узлы, выполняется дебаунс с `setTimeout` на **500 мс** (таймер сбрасывается и перезапускается на каждой партии), так что фильтр запускается через 500 мс после последней серии добавленных узлов. Фильтр также запускается один раз при начальной загрузке и один раз сразу после загрузки настроек.

  > ℹ️ Это дебаунс по заднему фронту, а не фиксированный троттлинг: при непрерывных мутациях проход продолжает откладываться. (Собственный встроенный комментарий в исходнике, `// Run at most every 500ms`, описывает троттлинг и немного неточен.)
- **Определение «Микс» / Shorts** — списки «Микс» определяются по `start_radio=1`, `list=RD`, оверлей-бейджу `MIX` или `ytd-radio-renderer`; Shorts — по ссылкам `/shorts/`, оверлей-бейджу `SHORTS`, `ytd-reel-item-renderer` и полкам `ytd-rich-shelf-renderer`.
- **Скрытие родительской секции баннера** — когда у совпавшего баннера есть предок `closest('ytd-rich-section-renderer')`, скрывается вся родительская секция, а не только внутренний баннер.

<a id="live-detection"></a>

Статус трансляции определяется по DOM-бейджам (`.badge-style-type-live-now`, `.badge-style-type-live-now-alternate`, `[overlay-style="LIVE"]`) или по самому тексту количества просмотров (без учёта регистра содержащему `視聴中`, `watching`, `live` или `ライブ`, плюс собственные ключевые слова трансляции активной локали страницы — см. [Интернационализация](#internationalization)).

<a id="internationalization"></a>

### Интернационализация

YouTube форматирует количество просмотров/зрителей по-разному на каждом языке интерфейса, поэтому разбор количеств определяется **обнаруженным языком страницы YouTube**, а не языком интерфейса всплывающего окна. На каждом проходе контент-скрипт читает `document.documentElement.lang` (с возвратом к `navigator.language`, затем `'en'`), нормализует его до базового кода языка (например, `zh-Hans-CN` → `zh`, `es-419` → `es`) и выбирает спецификацию для конкретной локали, описывающую десятичный разделитель этого языка, разделитель тысяч, единицы сокращений (например, `K`/`M`/`B`, `万`/`億`, `Mio.`/`Mrd.`, `тыс.`/`млн`/`млрд`, `万`/`亿`), соединительные слова «просмотры», маркеры дат/прошедших трансляций, слова для прямых эфиров и слова «нет просмотров» → `0`.

Корректный для локали разбор поддерживается для **9 языков**:

- **English** (`en`)
- **日本語** (`ja`)
- **Español** (`es`)
- **Português** (`pt`)
- **Deutsch** (`de`)
- **Français** (`fr`)
- **Русский** (`ru`)
- **한국어** (`ko`)
- **简体中文** (`zh`)

Если язык страницы не входит в этот список, разбор использует запасную **либеральную универсальную спецификацию**, в которой используется десятичный разделитель `.` и распознаётся объединение распространённых единиц (`K`/`M`/`B` и единиц CJK/корейских) по принципу наилучших усилий. Эта учётность локали исправляет прежние ошибки парсера на локалях с десятичной запятой (`de` / `fr` / `ru` / `pt`), где `1,7 Mrd.` читалось как `1` или `17` вместо `1 700 000 000`.

### Всплывающее окно (React)

Всплывающее окно на React 19 (`src/entrypoints/popup/`) отображает ползунки, переключатели, селектор режима фильтра и трёхпозиционный селектор языка. Редактирование любого элемента управления немедленно записывается в хранилище. Всплывающее окно определяет свой действующий язык отображения из `settings.language`: `auto` следует за `navigator.language`, тогда как `ja` / `en` закрепляют его.

### Хранение настроек и живая синхронизация

- Настройки сохраняются в `browser.storage.local` как **плоские ключи верхнего уровня** — по одному ключу на поле (`minViews`, `minConcurrent`, `filterMode`, …). Это соответствует форме `chrome.storage.local` до перехода на WXT, поэтому существующие пользователи сохраняют свои настройки после миграции.
- `loadSettings()` вызывает `browser.storage.local.get(defaultSettings)`, накладывая сохранённые значения поверх значений по умолчанию; `saveSettings()` вызывает `browser.storage.local.set(settings)`.
- `watchSettings()` регистрирует слушатель `browser.storage.onChanged`. При любом изменении в области `local` он перечитывает полную запись настроек и заново запускает фильтр — именно поэтому правки во всплывающем окне применяются мгновенно к открытым вкладкам.

Тип `Settings` имеет ровно 9 полей: `minViews`, `minConcurrent`, `filterMode`, `enableVideoFilter`, `enableLiveFilter`, `enableBannerFilter`, `enableMixFilter`, `enableShortsFilter`, `language` (`'auto' | 'ja' | 'en'`, по умолчанию `'auto'`).

### Разбор количества просмотров

`parseViewCount(text, lang)` определяет спецификацию локали для заданного языка страницы (или универсальную спецификацию, когда язык неизвестен/опущен) и нормализует разнообразные строки количеств YouTube в число (или `null`). Для всех поддерживаемых локалей он:

| Шаблон входных данных | Обработка | Пример |
|---|---|---|
| Единицы сокращений (для каждой локали) | умножается на множитель единицы локали | `1.2万` → `12000`, `12K` → `12000`, `1,7 Mrd.` (de) → `1700000000` |
| Десятичный разделитель / разделители тысяч локали | локали с десятичной запятой (`de`/`fr`/`ru`/`pt`) и локали с пробелом-разделителем тысяч (`fr`/`ru`) разбираются корректно | `129.069 Aufrufe` (de) → `129069` |
| Слова «нет просмотров» (например, `No views`, `なし`, эквиваленты в локали) | возвращает `0` | `No views` → `0` |
| Простые числа | разделители убираются по локали, затем разбираются | `1,234` (en) → `1234` |
| Текст дат / прошедших трансляций | трактуется как «не количество», поэтому карточка остаётся нетронутой | `2 days ago`, `〜前` |
| Не поддающееся разбору | возвращает `null` (элемент не фильтруется правилами по количеству просмотров) | — |

Перед разбором ключевые слова «просмотры»/соединительные слова локали (например, `views` / `view` / `回視聴` / `視聴` / `回` / `de vistas` / `Aufrufe` / `просмотров` / `조회수` / `次观看`) убираются. Пробелы — включая NBSP и узкий NBSP в том виде, в котором они встречаются в реальных строках YouTube — нормализуются в первую очередь. Помощник `isLive(text, lang)` возвращает `true` (без учёта регистра), когда текст содержит универсальный маркер трансляции (`視聴中`, `watching`, `live`, `ライブ`) или одно из слов активной локали, обозначающих прямой эфир.

## Известные ограничения

> ⚠️ Отладочное логирование в `src/utils/filter.ts` сейчас жёстко включено (`const debug = true`), поэтому контент-скрипт выводит подробный вывод в консоль. Сводный лог `FILTERED` выводится безусловно — он находится вне ограждения `debug` — поэтому появляется, даже если флаг выключен.

## Разработка

### Предварительные требования

- **Node.js 20** (версия, используемая в CI).
- npm (репозиторий поставляется с `package-lock.json`).

### Установка

```bash
npm ci   # postinstall runs `wxt prepare` to generate WXT-managed types (.wxt/)
```

### npm-скрипты

| Скрипт | Команда | Что делает |
|---|---|---|
| `dev` | `wxt` | Запускает dev-сервер WXT для Chrome (цель по умолчанию) с HMR. |
| `dev:firefox` | `wxt -b firefox` | Запускает dev-сервер WXT с целью Firefox. |
| `build` | `wxt build` | Продакшн-сборка для Chrome → `.output/chrome-mv3`. |
| `build:firefox` | `wxt build -b firefox` | Продакшн-сборка для Firefox → `.output/firefox-mv3`. |
| `zip` | `wxt zip` | Собирает и упаковывает расширение Chrome в распространяемый zip в `.output/`. |
| `zip:firefox` | `wxt zip -b firefox` | Собирает и упаковывает zip расширения Firefox в `.output/`. |
| `compile` | `wxt prepare && tsc --noEmit` | Генерирует типы WXT, затем выполняет проверку типов без эмиссии. |
| `lint` | `eslint .` | Линтит весь проект (плоская конфигурация ESLint 9 в `eslint.config.js`). |
| `test` | `tsx test-parser.ts` | Запускает тесты парсера количества просмотров для локалей (`test-parser.ts`), охватывающие разбор просмотров/зрителей и определение трансляций на всех 9 поддерживаемых языках. |

> ℹ️ `postinstall` автоматически запускает `wxt prepare` после `npm install` / `npm ci`.

Запускайте `npm test` после изменения чего-либо в `src/utils/locales.ts` или `src/utils/parser.ts` — он проверяет, что реальные строки количеств YouTube (включая формы с разделителем NBSP и десятичной запятой) разбираются в ожидаемые числа для English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어 и 简体中文.

WXT настроен с `srcDir: 'src'` и `modules: ['@wxt-dev/module-react']`. Общая логика импортируется через псевдоним `@/utils/...`. ## Сборка и выпуск

### Результаты сборки

| Цель | Выходной каталог |
|---|---|
| Chrome | `.output/chrome-mv3` |
| Firefox | `.output/firefox-mv3` |

### Zip-артефакты

`wxt zip` упаковывает сборку в `.output/`, используя стандартный шаблон имени zip-файла WXT (`{{name}}-{{version}}-{{browser}}.zip`, где `{{name}}` — это имя из `package.json` `tube-filter`). В `wxt.config.ts` не задан собственный шаблон `zipFileName`/`sources`, поэтому имена ниже соответствуют значениям WXT по умолчанию:

- `tube-filter-<version>-chrome.zip` (например, `tube-filter-1.0.0-chrome.zip`) — подтверждается glob-выражением загрузки в workflow выпуска.
- `tube-filter-<version>-firefox.zip` (например, `tube-filter-1.0.0-firefox.zip`) — подтверждается glob-выражением загрузки в workflow выпуска.
- Zip с исходным кодом для проверки AMO (стандартный для цели Firefox в WXT, обычно `tube-filter-<version>-sources.zip`). Это имя является значением WXT по умолчанию и не упоминается никаким кодом в репозитории; выполните `npm run zip:firefox`, чтобы подтвердить точное имя файла в вашем окружении.

### Workflow выпуска GitHub Actions

`.github/workflows/release.yml` (с названием **Release**) срабатывает на событие GitHub `release` с `types: [published]` и имеет `permissions: contents: write`. Задание выполняется на `ubuntu-latest` и:

1. Извлекает код (`actions/checkout@v4`).
2. Настраивает **Node.js 20** с кешем npm (`actions/setup-node@v4`).
3. Запускает `npm ci` (его `postinstall` запускает `wxt prepare`).
4. Запускает `npm run zip` (Chrome) и `npm run zip:firefox` (Firefox), создавая zip для обоих браузеров.
5. Загружает их как ресурсы выпуска через `softprops/action-gh-release@v2` (защищённый условием `startsWith(github.ref, 'refs/tags/')`), сопоставляя `.output/tube-filter-*-chrome.zip` и `.output/tube-filter-*-firefox.zip`.
