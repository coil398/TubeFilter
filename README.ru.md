# TubeFilter

[English](./README.md) · [日本語](./README.ja.md) · [Español](./README.es.md) · [Português](./README.pt.md) · [Deutsch](./README.de.md) · [Français](./README.fr.md) · [Русский](./README.ru.md) · [한국어](./README.ko.md) · [简体中文](./README.zh.md)

**TubeFilter** — это кроссбраузерное расширение на Manifest V3, которое наводит порядок в вашей ленте YouTube, фильтруя контент по задаваемым вами порогам количества просмотров и числа зрителей трансляций. Оно затемняет или скрывает видео с малым числом просмотров и трансляции с малым числом зрителей, а также может независимо убирать рекламные верхние баннеры, списки Mix и Shorts. Настройки хранятся во всплывающем окне на React, применяются мгновенно к открытым вкладкам YouTube без перезагрузки, а интерфейс всплывающего окна доступен на японском и английском (плюс режим **Auto**, который следует за языком вашего браузера). Количество просмотров и зрителей разбирается с учётом локали на **9 языках страниц YouTube**.

## Краткий обзор

TubeFilter скрывает или затемняет элементы ленты YouTube, которые не достигают заданных вами порогов просмотров/зрителей, и при необходимости может убирать баннеры, списки Mix и Shorts. Чтобы попробовать его за три шага:

1. `npm ci`
2. `npm run build` (Chrome) или `npm run build:firefox` (Firefox)
3. Загрузите распакованную сборку из `.output/chrome-mv3` (или `.output/firefox-mv3`) — см. [Установка](#installation-end-users).

Ваши настройки никогда не покидают браузер: TubeFilter запрашивает только разрешение `storage` и доступ к хосту `youtube.com`, а вся конфигурация хранится в локальном хранилище браузера.

## Возможности

### Фильтр по количеству просмотров (обычные видео)

Обычное видео фильтруется, когда выполняются **все** перечисленные условия:

- Фильтр видео включён (`enableVideoFilter`).
- Количество просмотров успешно распознано из карточки.
- Распознанное количество просмотров **ниже** вашего порога `minViews`.

Если у видео нет распознаваемого количества просмотров, оно остаётся нетронутым. Ползунок **Min Views** во всплывающем окне управляет порогом и отключается, когда фильтр видео выключен.

### Фильтр трансляций (прямые эфиры)

Прямые эфиры оцениваются по **отдельному** порогу — по числу одновременных зрителей, а не по общему количеству просмотров. Прямой эфир фильтруется, когда фильтр трансляций включён (`enableLiveFilter`), число зрителей распознано, и это число **ниже** вашего порога `minConcurrent`. Статус трансляции определяется по DOM-меткам live-now или по тексту, указывающему на трансляцию, в строке количества просмотров (см. [Как это работает](#live-detection)).

### Фильтры контента (без порога)

Эти три фильтра представляют собой безусловные переключатели вкл/выкл — они полностью игнорируют количество просмотров:

| Фильтр | Настройка | Что убирает |
|---|---|---|
| **Top Banner** | `enableBannerFilter` | Рекламные баннеры-шапки и баннеры с заявлениями/промоакциями. Когда найденный баннер находится внутри rich-секции, скрывается вся родительская секция. |
| **Mix Lists** | `enableMixFilter` | Автоматически генерируемые плейлисты Mix / радио. |
| **Shorts** | `enableShortsFilter` | Ссылки и полки Shorts. |

### Режимы фильтрации: Hide или Opacity

Селектор **Filter Mode** определяет, как обрабатываются отфильтрованные видео/трансляции:

- **Hide** — устанавливает `display: none`, полностью убирая элемент из вида.
- **Opacity** — устанавливает `opacity: 0.1`, затемняя элемент до **10 %** непрозрачности, оставляя его видимым. Это значение по умолчанию.

> ℹ️ Фильтр Top Banner всегда скрывает баннеры (`display: none`) независимо от выбранного режима фильтрации. Режим фильтрации влияет только на видео и трансляции.

### Приоритет фильтров

Каждая карточка классифицируется один раз, в фиксированном порядке if/else. Применяется только правило первой совпавшей категории:

1. **Shorts** (наивысший приоритет)
2. **Списки Mix**
3. **Прямые эфиры**
4. **Обычные видео**

### Многоязычное распознавание количества просмотров

YouTube отображает количество просмотров и зрителей **очень по-разному в зависимости от языка страницы** — это не только переведённые слова, но и разные разделители дробной/тысячной части и единицы сокращения. Одно и то же количество около 1,7 миллиарда отображается как:

| Язык | Строка YouTube |
|---|---|
| English | `1.7B` |
| Deutsch | `1,7 Mrd.` |
| 日本語 | `17億` |
| Русский | `1,7 млрд` |
| 简体中文 | `17亿` |

Контент-скрипт автоматически определяет **язык страницы YouTube** (`document.documentElement.lang`) и разбирает количества с правильным десятичным разделителем, разделителем тысяч и единицами сокращения для этой локали. Это важно, потому что предыдущий парсер предполагал английский формат и **неверно читал локали с запятой-разделителем дробной части** (`de` / `fr` / `ru` / `pt`) — например, читал `1,7 Mrd.` как `1` или `17` вместо `1 700 000 000`. Корректный для локали разбор поддерживается для **9 языков** (см. [Интернационализация](#internationalization)); для неизвестных языков страниц происходит откат к универсальному либеральному парсеру.

### Языки (интерфейс всплывающего окна)

Интерфейс всплывающего окна предлагается на **японском (`ja`)** и **английском (`en`)**, а также имеет третий режим **Auto (`auto`, по умолчанию)**, который следует за языком интерфейса браузера (`navigator.language`): если язык браузера начинается с `ja`, интерфейс отображается на японском, иначе — на английском. Трёхкнопочный элемент управления в заголовке всплывающего окна (`Auto` / `日本語` / `EN`) переключает между ними, при этом активный выбор подсвечивается.

## Использование

Откройте всплывающее окно расширения, чтобы настроить фильтрацию. Изменения сохраняются немедленно и применяются «на лету» к любой открытой вкладке YouTube — без перезагрузки.

### Справочник по настройкам

| Настройка | Что контролирует | Диапазон / шаг | По умолчанию | Метка JA | Метка EN |
|---|---|---|---|---|---|
| `minViews` | Минимальное количество просмотров, ниже которого обычные видео фильтруются | диапазон `0`–`100000`, шаг `1000` | `1000` | 最低再生回数 | Min Views |
| `minConcurrent` | Минимальное число одновременных зрителей, ниже которого фильтруются прямые эфиры | диапазон `0`–`5000`, шаг `50` | `50` | 最低同時接続数 (ライブ) | Min Concurrent (Live) |
| `filterMode` | Как обрабатываются отфильтрованные видео/трансляции (`hide` / `opacity`) | двухкнопочный селектор | `opacity` | フィルタリングモード | Filter Mode |
| `enableVideoFilter` | Включает/отключает фильтр по количеству просмотров (также включает/отключает ползунок Min Views) | переключатель вкл/выкл | `true` | 動画フィルタ有効 | Enable Video Filter |
| `enableLiveFilter` | Включает/отключает фильтр трансляций (также включает/отключает ползунок Min Concurrent) | переключатель вкл/выкл | `true` | ライブフィルタ有効 | Enable Live Filter |
| `enableBannerFilter` | Скрывает рекламные верхние баннеры | переключатель вкл/выкл | `true` | トップバナー非表示 | Hide Top Banner |
| `enableMixFilter` | Скрывает списки Mix | переключатель вкл/выкл | `true` | ミックスリスト非表示 | Hide Mix Lists |
| `enableShortsFilter` | Скрывает Shorts | переключатель вкл/выкл | `true` | ショート動画非表示 | Hide Shorts |
| `language` | Язык интерфейса всплывающего окна (`auto` / `ja` / `en`); режим **Auto** следует за языком интерфейса браузера (`navigator.language`) | трёхкнопочный селектор (`Auto` / `日本語` / `EN`) | `auto` | Language | 言語 |

Оба ползунка показывают своё значение с разделителями тысяч через `toLocaleString()`. Под ползунком Min Concurrent расположена вспомогательная подсказка:

- JA: 視聴者数が少ないライブ配信はフィルタリングされます。
- EN: Live streams with fewer viewers will be filtered.

### Селектор режима фильтрации

Двухкнопочный элемент управления. **Hide** устанавливает `filterMode = 'hide'`; **Opacity** устанавливает `filterMode = 'opacity'`. Активный режим подсвечивается. Метки локализованы — JA: 非表示 / 薄く表示, EN: Hide / Opacity.

### Селектор языка

Трёхкнопочный элемент управления в заголовке всплывающего окна устанавливает `language` в одно из значений `auto`, `ja` или `en`. Кнопки подписаны как **Auto** / **日本語** / **EN**, и активный выбор подсвечивается. Режим **Auto** (по умолчанию) определяет фактический язык интерфейса по `navigator.language`: язык браузера, начинающийся с `ja`, отображает интерфейс на японском, любой другой — на английском. Выбор **日本語** или **EN** фиксирует интерфейс на этом языке независимо от настройки браузера.

## Как это работает

### Контент-скрипт

- **Совпадение и тайминг** — совпадает с `https://www.youtube.com/*` и запускается на `run_at: document_end`.
- **Определение языка страницы** — при каждом проходе он читает `document.documentElement.lang` (с откатом к `navigator.language`, затем к `'en'`) и использует это для выбора корректного для локали парсера количества просмотров (см. [Интернационализация](#internationalization)).
- **Цели** — сканирует 7 селекторов видео, охватывающих Главную (`ytd-rich-item-renderer`), Поиск (`ytd-video-renderer`), Боковую панель (`ytd-compact-video-renderer`), Канал (`ytd-grid-video-renderer`), списки Mix (`ytd-radio-renderer`), отдельные Shorts (`ytd-reel-item-renderer`) и полку Shorts (`ytd-rich-shelf-renderer`); плюс 9 селекторов баннеров (`#masthead-ad`, `#big-yoodle`, `ytd-statement-banner-renderer`, `ytd-banner-promo-renderer`, `ytd-ad-slot-renderer`, `ytd-in-feed-ad-layout-renderer` и несколько вариантов `ytd-rich-section-renderer > #content > …`).
- **Обработка динамической ленты** — `MutationObserver` наблюдает за `document.body` с `{ childList: true, subtree: true }`. Когда узлы добавляются, он применяет debounce с `setTimeout` на **500 мс** (сбрасывая и перезапуская таймер при каждой партии), так что фильтр запускается через 500 мс после последнего всплеска добавленных узлов. Фильтр также запускается один раз при первоначальной загрузке и один раз сразу после загрузки настроек.

  > ℹ️ Это завершающий debounce, а не фиксированный throttle: при непрерывных изменениях проход продолжает откладываться. (Собственный встроенный комментарий в исходнике, `// Run at most every 500ms`, описывает throttling и слегка неточен.)
- **Определение Mix / Shorts** — списки Mix распознаются по `start_radio=1`, `list=RD`, наложенной метке `MIX` или `ytd-radio-renderer`; Shorts — по ссылкам `/shorts/`, наложенной метке `SHORTS`, `ytd-reel-item-renderer` и полкам `ytd-rich-shelf-renderer`.
- **Скрытие родительской секции баннера** — когда у найденного баннера есть предок `closest('ytd-rich-section-renderer')`, скрывается вся родительская секция, а не только внутренний баннер.

<a id="live-detection"></a>

Статус трансляции определяется по DOM-меткам (`.badge-style-type-live-now`, `.badge-style-type-live-now-alternate`, `[overlay-style="LIVE"]`) или по самому тексту количества просмотров (без учёта регистра содержащему `視聴中`, `watching`, `live` или `ライブ`, плюс собственные ключевые слова трансляции для текущей локали страницы — см. [Интернационализация](#internationalization)).

<a id="internationalization"></a>

### Интернационализация

YouTube форматирует количество просмотров/зрителей по-разному в каждом языке интерфейса, поэтому разбор количеств управляется **определённым языком страницы YouTube**, а не языком интерфейса всплывающего окна. При каждом проходе контент-скрипт читает `document.documentElement.lang` (с откатом к `navigator.language`, затем к `'en'`), нормализует его до базового кода языка (например, `zh-Hans-CN` → `zh`, `es-419` → `es`) и выбирает спецификацию для конкретной локали, описывающую десятичный разделитель этого языка, разделитель тысяч, единицы сокращения (например, `K`/`M`/`B`, `万`/`億`, `Mio.`/`Mrd.`, `тыс.`/`млн`/`млрд`, `万`/`亿`), слова-связки «просмотры», маркеры даты/прошедшей трансляции, слова для прямых эфиров и слова «нет просмотров» → `0`.

Корректный для локали разбор поддерживается для **9 языков**:

- **English** (`en`)
- **日本語** (`ja`)
- **Español** (`es`)
- **Português** (`pt`)
- **Deutsch** (`de`)
- **Français** (`fr`)
- **Русский** (`ru`)
- **한국어** (`ko`)
- **简体中文** (`zh`)

Если язык страницы не входит в этот список, разбор откатывается к **универсальной либеральной спецификации**, которая использует `.` в качестве десятичного разделителя и распознаёт объединение распространённых единиц (`K`/`M`/`B` и единицы CJK/корейского) по принципу наилучших усилий. Эта осведомлённость о локали исправляет прежние ошибки парсера при чтении локалей с запятой-разделителем дробной части (`de` / `fr` / `ru` / `pt`), где `1,7 Mrd.` читался как `1` или `17` вместо `1 700 000 000`.

### Всплывающее окно (React)

Всплывающее окно на React 19 (`src/entrypoints/popup/`) отображает ползунки, переключатели, селектор режима фильтрации и трёхпозиционный селектор языка. Редактирование любого элемента управления немедленно записывается в хранилище. Всплывающее окно определяет свой фактический язык отображения по `settings.language`: `auto` следует за `navigator.language`, тогда как `ja` / `en` фиксируют его.

### Хранение настроек и живая синхронизация

- Настройки сохраняются в `browser.storage.local` как **плоские ключи верхнего уровня** — по одному ключу на поле (`minViews`, `minConcurrent`, `filterMode`, …). Это соответствует форме `chrome.storage.local` до перехода на WXT, поэтому существующие пользователи сохраняют свои настройки при миграции.
- `loadSettings()` вызывает `browser.storage.local.get(defaultSettings)`, накладывая сохранённые значения поверх значений по умолчанию; `saveSettings()` вызывает `browser.storage.local.set(settings)`.
- `watchSettings()` регистрирует слушатель `browser.storage.onChanged`. При любом изменении в области `local` он перечитывает полную запись настроек и повторно запускает фильтр — именно поэтому изменения во всплывающем окне применяются мгновенно к открытым вкладкам.

Тип `Settings` имеет ровно 9 полей: `minViews`, `minConcurrent`, `filterMode`, `enableVideoFilter`, `enableLiveFilter`, `enableBannerFilter`, `enableMixFilter`, `enableShortsFilter`, `language` (`'auto' | 'ja' | 'en'`, по умолчанию `'auto'`).

### Разбор количества просмотров

`parseViewCount(text, lang)` определяет спецификацию локали для заданного языка страницы (или универсальную спецификацию, когда язык неизвестен/опущен) и нормализует разнообразные строки количеств YouTube в число (или `null`). Во всех поддерживаемых локалях он:

| Входной шаблон | Обработка | Пример |
|---|---|---|
| Единицы сокращения (по локали) | умножается на коэффициент единицы локали | `1.2万` → `12000`, `12K` → `12000`, `1,7 Mrd.` (de) → `1700000000` |
| Десятичные разделители / разделители тысяч локали | локали с запятой-разделителем дробной части (`de`/`fr`/`ru`/`pt`) и локали с пробелом-разделителем тысяч (`fr`/`ru`) разбираются корректно | `129.069 Aufrufe` (de) → `129069` |
| Слова «нет просмотров» (например, `No views`, `なし`, эквиваленты локали) | возвращает `0` | `No views` → `0` |
| Простые числа | разделители удаляются согласно локали, затем разбираются | `1,234` (en) → `1234` |
| Текст даты / прошедшей трансляции | трактуется как «не количество», поэтому карточка остаётся нетронутой | `2 days ago`, `〜前` |
| Неразбираемое | возвращает `null` (элемент не фильтруется по правилам количества просмотров) | — |

Перед разбором ключевые слова «просмотры»/связки локали (например, `views` / `view` / `回視聴` / `視聴` / `回` / `de vistas` / `Aufrufe` / `просмотров` / `조회수` / `次观看`) удаляются. Пробельные символы — включая NBSP и узкий NBSP в том виде, в каком они встречаются в реальных строках YouTube — нормализуются первыми. Вспомогательная функция `isLive(text, lang)` возвращает `true` (без учёта регистра), когда текст содержит универсальный маркер трансляции (`視聴中`, `watching`, `live`, `ライブ`) или одно из слов для прямых эфиров текущей локали.

## Известные ограничения

> ⚠️ Отладочное логирование в `src/utils/filter.ts` сейчас жёстко включено (`const debug = true`), поэтому контент-скрипт выдаёт подробный вывод в консоль. Сводный лог `FILTERED` выдаётся безусловно — он находится вне ограждения `debug` — поэтому он появляется, даже если флаг выключен.


### npm-скрипты

| Скрипт | Команда | Что делает |
|---|---|---|
| `dev` | `wxt` | Запускает dev-сервер WXT для Chrome (цель по умолчанию) с HMR. |
| `dev:firefox` | `wxt -b firefox` | Запускает dev-сервер WXT с целью Firefox. |
| `build` | `wxt build` | Production-сборка для Chrome → `.output/chrome-mv3`. |

| `zip:firefox` | `wxt zip -b firefox` | Собирает и упаковывает zip расширения Firefox в `.output/`. |
| `compile` | `wxt prepare && tsc --noEmit` | Генерирует типы WXT, затем выполняет проверку типов без эмиссии. |

> ℹ️ `postinstall` автоматически запускает `wxt prepare` после `npm install` / `npm ci`.

Запускайте `npm test` после изменения чего-либо в `src/utils/locales.ts` или `src/utils/parser.ts` — он проверяет, что реальные строки количеств YouTube (включая формы с разделителем NBSP и с запятой-разделителем дробной части) разбираются в ожидаемые числа для English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어 и 简体中文.

WXT настроен с `srcDir: 'src'` и `modules: ['@wxt-dev/module-react']`. Общая логика импортируется через псевдоним `@/utils/...`. ## Сборка и выпуск

### Результаты сборки

| Цель | Каталог вывода |
|---|---|
| Chrome | `.output/chrome-mv3` |
| Firefox | `.output/firefox-mv3` |

### Zip-артефакты

`wxt zip` упаковывает сборку в `.output/`, используя стандартный шаблон имени zip-файла WXT (`{{name}}-{{version}}-{{browser}}.zip`, где `{{name}}` — это имя из `package.json`, `tube-filter`). В `wxt.config.ts` не задан пользовательский шаблон `zipFileName`/`sources`, поэтому имена ниже следуют значениям WXT по умолчанию:

- `tube-filter-<version>-chrome.zip` (например, `tube-filter-1.0.0-chrome.zip`) — подтверждается glob-шаблоном загрузки в workflow выпуска.
- `tube-filter-<version>-firefox.zip` (например, `tube-filter-1.0.0-firefox.zip`) — подтверждается glob-шаблоном загрузки в workflow выпуска.
- Zip с исходниками для проверки AMO (значение WXT по умолчанию для цели Firefox, обычно `tube-filter-<version>-sources.zip`). Это имя — значение WXT по умолчанию и не упоминается в коде репозитория; выполните `npm run zip:firefox`, чтобы подтвердить точное имя файла в вашем окружении.

### Workflow выпуска GitHub Actions

`.github/workflows/release.yml` (с именем **Release**) срабатывает по событию GitHub `release` с `types: [published]` и имеет `permissions: contents: write`. Задание выполняется на `ubuntu-latest` и:

1. Извлекает код (`actions/checkout@v4`).
2. Настраивает **Node.js 20** с кешем npm (`actions/setup-node@v4`).
3. Выполняет `npm ci` (его `postinstall` запускает `wxt prepare`).
4. Выполняет `npm run zip` (Chrome) и `npm run zip:firefox` (Firefox), создавая zip для обоих браузеров.
5. Загружает их как ассеты выпуска через `softprops/action-gh-release@v2` (защищено условием `startsWith(github.ref, 'refs/tags/')`), сопоставляя `.output/tube-filter-*-chrome.zip` и `.output/tube-filter-*-firefox.zip`.
