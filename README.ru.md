# TubeFilter

[English](./README.md) · [日本語](./README.ja.md) · [Español](./README.es.md) · [Português](./README.pt.md) · [Deutsch](./README.de.md) · [Français](./README.fr.md) · [Русский](./README.ru.md) · [한국어](./README.ko.md) · [简体中文](./README.zh.md)

**TubeFilter** — это кроссбраузерное расширение на Manifest V3, которое наводит порядок в вашей ленте YouTube, фильтруя контент по задаваемым вами порогам количества просмотров и числа зрителей трансляций. Оно затемняет или скрывает видео с малым числом просмотров и трансляции с малым числом зрителей, а также может независимо вырезать рекламные верхние баннеры, списки Mix и Shorts. Настройки находятся в React-попапе, мгновенно применяются к открытым вкладкам YouTube без перезагрузки, а интерфейс попапа доступен на **9 языках** (English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어, 简体中文) с режимом **Auto**, который следует за языком вашего браузера. Количество просмотров и зрителей разбирается с учётом локали на тех же **9 языках страниц YouTube**.

## Краткий обзор

TubeFilter скрывает или затемняет элементы ленты YouTube, которые не дотягивают до заданных вами порогов просмотров/зрителей, и по запросу может вырезать баннеры, списки Mix и Shorts. Чтобы попробовать за три шага:

1. `npm ci`
2. `npm run build` (Chrome) или `npm run build:firefox` (Firefox)
3. Загрузите распакованную сборку из `.output/chrome-mv3` (или `.output/firefox-mv3`) — см. [Установка](#installation-end-users).

Ваши настройки никогда не покидают браузер: TubeFilter запрашивает только разрешение `storage` и доступ к хосту `youtube.com`, а вся конфигурация хранится в локальном хранилище браузера.

## Возможности

### Фильтр по количеству просмотров (обычные видео)

Обычное видео фильтруется, когда **все** перечисленные условия выполнены:

- Фильтр видео включён (`enableVideoFilter`).
- Количество просмотров успешно разобрано из карточки.
- Разобранное количество просмотров **ниже** вашего порога `minViews`.

Если у видео нет читаемого количества просмотров, оно остаётся нетронутым. Ползунок **Min Views** в попапе управляет порогом и отключается, когда фильтр видео выключен.

### Фильтр трансляций (прямые эфиры)

Прямые трансляции оцениваются по **отдельному** порогу — числу одновременных зрителей, а не суммарным просмотрам. Трансляция фильтруется, когда фильтр трансляций включён (`enableLiveFilter`), количество зрителей разобрано и это количество **ниже** вашего порога `minConcurrent`. Статус трансляции определяется по DOM-бейджам «в эфире» или по тексту, указывающему на эфир, в строке количества просмотров (см. [Как это работает](#live-detection)).

### Контентные фильтры (без порога)

Эти три фильтра — безусловные переключатели вкл/выкл, они полностью игнорируют количество просмотров:

| Фильтр | Настройка | Что удаляет |
|---|---|---|
| **Верхний баннер** | `enableBannerFilter` | Рекламные баннеры-шапки и информационные/промо-баннеры. Если найденный баннер находится внутри rich-секции, скрывается вся родительская секция. |
| **Списки Mix** | `enableMixFilter` | Автоматически создаваемые плейлисты Mix / radio. |
| **Shorts** | `enableShortsFilter` | Ссылки и полки Shorts. |

### Правила для каналов и фильтр по ключевым словам

Помимо числовых порогов, вы можете жёстко разрешать или жёстко скрывать видео по каналу, а также скрывать по тексту заголовка — всё это управляется в попапе списками с одной записью на строку.

- **Всегда скрывать каналы** (`channelBlocklist`) — видео с этих каналов всегда скрыты, независимо от количества просмотров.
- **Всегда показывать каналы** (`channelAllowlist`) — видео с этих каналов никогда не фильтруются (удобно для любимых небольших авторов с количеством просмотров ниже `minViews`).
- **Скрывать заголовки, содержащие** (`titleKeywords`) — скрывать видео, заголовок которых содержит любой из перечисленных терминов. Запись, заключённая в слэши (например, `/spoiler.*ending/`), трактуется как **регулярное выражение** без учёта регистра; иначе это обычная подстрока без учёта регистра.

Каналы сопоставляются **точно** по `@handle`, идентификатору канала или имени канала (поэтому `mr` **не** совпадает с `@MrBeast`). Эти правила применяются к отдельным карточкам видео / плейлистов / Mix, но **не** к сводным полкам (например, полке Shorts), так что один дочерний элемент никогда не скрывает целый ряд.

### Где применяется фильтрация

Контент-скрипт работает по всему YouTube и заново фильтрует по мере навигации — Главная, Поиск, Подписки, рекомендации в боковой панели страницы просмотра и страницы каналов — охватывая как устаревшие рендереры, так и более новую раскладку `yt-lockup-view-model`.

### Режимы фильтрации: Hide и Opacity

Селектор **Filter Mode** определяет, как обрабатываются отфильтрованные видео/трансляции:

- **Hide** — устанавливает `display: none`, полностью убирая элемент из вида.
- **Opacity** — устанавливает `opacity: 0.1`, затемняя элемент до **10 %** непрозрачности, но оставляя его видимым. Это значение по умолчанию.

> ℹ️ Фильтр верхнего баннера всегда скрывает баннеры (`display: none`) независимо от выбранного режима фильтрации. Режим фильтрации влияет только на видео и трансляции.

### Приоритет фильтров

Каждая карточка классифицируется один раз, в фиксированном порядке if/else. Применяется только правило первой совпавшей категории:

1. **Чёрный список каналов** — всегда скрывать (наивысший приоритет)
2. **Белый список каналов** — всегда показывать (пропускает все правила ниже)
3. **Ключевое слово в заголовке** — скрывать совпавшие заголовки
4. **Shorts**
5. **Списки Mix**
6. **Прямые трансляции**
7. **Обычные видео**

(Правила для каналов/ключевых слов 1–3 применяются только к отдельным карточкам, а не к сводным полкам.)

### Отключение авто-дубляжа (принудительно оригинальная аудиодорожка)

Автоматический дубляж YouTube заменяет аудио видео на дорожку, переведённую ИИ, исходя из языка вашего интерфейса — поэтому английское видео по умолчанию воспроизводится на японском, немецком и т. д. С функцией **Force Original Audio** (`forceOriginalAudio`, **включена по умолчанию**) TubeFilter определяет оригинальную аудиодорожку и автоматически переключает плеер на неё на каждом видео и Short, отменяя авто-дубляж.

- Работает на видео `/watch` и Shorts, повторно применяется при каждой навигации внутри приложения.
- Оригинальная дорожка определяется **независимо от языка** путём декодирования идентификатора аудиодорожки плеера (данные оригинальной дорожки содержат `original`; дублированные дорожки содержат `dubbed` / `dubbed-auto`).
- Реализовано через **скрипт в мире MAIN**, внедряемый в страницу — аудио-API плеера YouTube недоступен из изолированного мира контент-скрипта — а настройка передаётся из хранилища расширения.
- Отключите её в попапе в любой момент, чтобы сохранить дублированное аудио YouTube.

### Многоязычное определение количества просмотров

YouTube отображает количество просмотров и зрителей **совершенно по-разному в зависимости от языка страницы** — не только переведёнными словами, но и разными разделителями дробной части/тысяч и единицами сокращений. То же количество ~1,7 миллиарда выглядит как:

| Язык | Строка YouTube |
|---|---|
| English | `1.7B` |
| Deutsch | `1,7 Mrd.` |
| 日本語 | `17億` |
| Русский | `1,7 млрд` |
| 简体中文 | `17亿` |

Контент-скрипт автоматически определяет **язык страницы YouTube** (`document.documentElement.lang`) и разбирает количества с правильными для этой локали разделителем дробной части, разделителем тысяч и единицами сокращений. Это важно, потому что предыдущий парсер предполагал формат в английском стиле и **неправильно читал локали с запятой-десятичным разделителем** (`de` / `fr` / `ru` / `pt`) — например, читал `1,7 Mrd.` как `1` или `17` вместо `1 700 000 000`. Корректный для локали разбор поддерживается для **9 языков** (см. [Интернационализация](#internationalization)); для неизвестных языков страниц используется снисходительный универсальный парсер.

### Языки (интерфейс попапа)

Интерфейс попапа доступен на **9 языках** — English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어, 简体中文 — плюс режим **Auto (`auto`, по умолчанию)**, который следует за языком интерфейса браузера (`navigator.language`, сопоставленным с ближайшей поддерживаемой локалью, с откатом на английский). Выпадающий список в шапке попапа переключает между ними.

## Использование

Откройте попап расширения, чтобы настроить фильтрацию. Изменения сохраняются сразу и применяются вживую к любой открытой вкладке YouTube — перезагрузка не требуется.

- JA: 視聴者数が少ないライブ配信はフィルタリングされます。
- EN: Live streams with fewer viewers will be filtered.

### Селектор режима фильтрации

Элемент управления из двух кнопок. **Hide** устанавливает `filterMode = 'hide'`; **Opacity** устанавливает `filterMode = 'opacity'`. Активный режим подсвечивается. Подписи локализованы — JA: 非表示 / 薄く表示, EN: Hide / Opacity.

### Селектор языка

Выпадающий список в шапке попапа задаёт `language` в `auto` или в одну из 9 локалей (`en`/`ja`/`es`/`pt`/`de`/`fr`/`ru`/`ko`/`zh`). **Auto** (значение по умолчанию) определяет эффективный язык интерфейса по `navigator.language`, сопоставляя его с ближайшей поддерживаемой локалью и откатываясь на английский. Выбор конкретного языка фиксирует интерфейс на нём независимо от настройки браузера.

## Как это работает

### Контент-скрипт

- **Совпадение и тайминг** — совпадает с `https://www.youtube.com/*` и запускается на `run_at: document_end`.
- **Определение языка страницы** — при каждом проходе он читает `document.documentElement.lang` (с откатом на `navigator.language`, затем `'en'`) и использует это для выбора корректного для локали парсера количества просмотров (см. [Интернационализация](#internationalization)).
- **Цели** — сканирует 7 селекторов видео, охватывающих Главную (`ytd-rich-item-renderer`), Поиск (`ytd-video-renderer`), Боковую панель (`ytd-compact-video-renderer`), Канал (`ytd-grid-video-renderer`), списки Mix (`ytd-radio-renderer`), отдельные Shorts (`ytd-reel-item-renderer`) и полку Shorts (`ytd-rich-shelf-renderer`); плюс 9 селекторов баннеров (`#masthead-ad`, `#big-yoodle`, `ytd-statement-banner-renderer`, `ytd-banner-promo-renderer`, `ytd-ad-slot-renderer`, `ytd-in-feed-ad-layout-renderer` и несколько вариантов `ytd-rich-section-renderer > #content > …`).
- **Обработка динамической ленты** — `MutationObserver` следит за `document.body` с `{ childList: true, subtree: true }`. При добавлении узлов он применяет дебаунс с `setTimeout` на **500 мс** (сбрасывая и заново взводя таймер при каждом пакете), так что фильтр запускается через 500 мс после последнего всплеска добавленных узлов. Фильтр также запускается один раз при первоначальной загрузке и один раз сразу после загрузки настроек.

  > ℹ️ Это завершающий дебаунс, а не фиксированный троттлинг: при непрерывных мутациях проход продолжает откладываться. (Собственный встроенный комментарий в исходнике, `// Run at most every 500ms`, описывает троттлинг и слегка неточен.)
- **Определение Mix / Shorts** — списки Mix определяются по `start_radio=1`, `list=RD`, оверлейному бейджу `MIX` или `ytd-radio-renderer`; Shorts — по ссылкам `/shorts/`, оверлейному бейджу `SHORTS`, `ytd-reel-item-renderer` и полкам `ytd-rich-shelf-renderer`.
- **Скрытие родительской секции баннера** — когда у найденного баннера есть предок `closest('ytd-rich-section-renderer')`, скрывается вся родительская секция, а не только внутренний баннер.

<a id="live-detection"></a>

Статус трансляции определяется по DOM-бейджам (`.badge-style-type-live-now`, `.badge-style-type-live-now-alternate`, `[overlay-style="LIVE"]`) или по самому тексту количества просмотров (содержащему без учёта регистра `視聴中`, `watching`, `live` или `ライブ`, плюс собственные ключевые слова эфира для активной локали страницы — см. [Интернационализация](#internationalization)).

### Интернационализация

YouTube форматирует количество просмотров/зрителей по-разному на каждом языке интерфейса, поэтому разбор количеств управляется **определённым языком страницы YouTube**, а не языком интерфейса попапа. При каждом проходе контент-скрипт читает `document.documentElement.lang` (с откатом на `navigator.language`, затем `'en'`), нормализует его до базового кода языка (например, `zh-Hans-CN` → `zh`, `es-419` → `es`) и выбирает спецификацию для конкретной локали, описывающую её разделитель дробной части, разделитель тысяч, единицы сокращений (например, `K`/`M`/`B`, `万`/`億`, `Mio.`/`Mrd.`, `тыс.`/`млн`/`млрд`, `万`/`亿`), слова-связки «просмотры», маркеры даты/прошедшей трансляции, слова прямой трансляции и слова «нет просмотров» → `0`.

Корректный для локали разбор поддерживается для **9 языков**:

- **English** (`en`)
- **日本語** (`ja`)
- **Español** (`es`)
- **Português** (`pt`)
- **Deutsch** (`de`)
- **Français** (`fr`)
- **Русский** (`ru`)
- **한국어** (`ko`)
- **简体中文** (`zh`)

Если язык страницы не входит в этот список, разбор откатывается к **снисходительной универсальной спецификации**, которая использует `.` в качестве десятичного разделителя и по мере возможности распознаёт объединение распространённых единиц (`K`/`M`/`B` и единиц CJK/корейского языка). Эта осведомлённость о локали устраняет прежние ошибки чтения парсером локалей с запятой-десятичным разделителем (`de` / `fr` / `ru` / `pt`), где `1,7 Mrd.` читалось как `1` или `17` вместо `1 700 000 000`.

### Попап (React)

Попап на React 19 (`src/entrypoints/popup/`) отрисовывает ползунки, переключатели, селектор режима фильтрации и трёхпозиционный селектор языка. Редактирование любого элемента управления сразу пишет в хранилище. Попап определяет свой эффективный язык отображения из `settings.language`: `auto` следует за `navigator.language`, тогда как `ja` / `en` фиксируют его.

### Хранение настроек и живая синхронизация

- Настройки сохраняются в `browser.storage.local` как **плоские ключи верхнего уровня** — по одному ключу на поле (`minViews`, `minConcurrent`, `filterMode`, …). Это соответствует форме `chrome.storage.local` до перехода на WXT, так что существующие пользователи сохраняют свои настройки после миграции.
- `loadSettings()` вызывает `browser.storage.local.get(defaultSettings)`, накладывая сохранённые значения поверх значений по умолчанию; `saveSettings()` вызывает `browser.storage.local.set(settings)`.
- `watchSettings()` регистрирует слушатель `browser.storage.onChanged`. При любом изменении в области `local` он заново читает полную запись настроек и заново запускает фильтр — именно поэтому правки в попапе мгновенно применяются к открытым вкладкам.

Тип `Settings` имеет ровно 9 полей: `minViews`, `minConcurrent`, `filterMode`, `enableVideoFilter`, `enableLiveFilter`, `enableBannerFilter`, `enableMixFilter`, `enableShortsFilter`, `language` (`'auto' | 'ja' | 'en'`, по умолчанию `'auto'`).

### Разбор количества просмотров

`parseViewCount(text, lang)` определяет спецификацию локали для заданного языка страницы (или универсальную спецификацию, когда язык неизвестен/опущен) и нормализует разнообразные строки количеств YouTube в число (или `null`). Во всех поддерживаемых локалях он:

| Шаблон ввода | Обработка | Пример |
|---|---|---|
| Единицы сокращений (по локали) | умножается на коэффициент единицы локали | `1.2万` → `12000`, `12K` → `12000`, `1,7 Mrd.` (de) → `1700000000` |
| Десятичные разделители / разделители тысяч локали | локали с запятой-десятичным разделителем (`de`/`fr`/`ru`/`pt`) и локали с пробелом-разделителем тысяч (`fr`/`ru`) разбираются корректно | `129.069 Aufrufe` (de) → `129069` |
| Слова «нет просмотров» (например, `No views`, `なし`, эквиваленты локали) | возвращает `0` | `No views` → `0` |
| Обычные числа | разделители удаляются по локали, затем выполняется разбор | `1,234` (en) → `1234` |
| Текст даты / прошедшей трансляции | трактуется как «не количество», поэтому карточка остаётся нетронутой | `2 days ago`, `〜前` |
| Не поддающееся разбору | возвращает `null` (элемент не фильтруется по правилам количества просмотров) | — |

Перед разбором удаляются ключевые слова локали «просмотры»/связки (например, `views` / `view` / `回視聴` / `視聴` / `回` / `de vistas` / `Aufrufe` / `просмотров` / `조회수` / `次观看`). Пробельные символы — включая NBSP и узкий NBSP в том виде, в каком они встречаются в реальных строках YouTube — сначала нормализуются. Помощник `isLive(text, lang)` возвращает `true` (без учёта регистра), когда текст содержит универсальный маркер эфира (`視聴中`, `watching`, `live`, `ライブ`) или одно из слов прямой трансляции активной локали.

## Известные ограничения

> ⚠️ Отладочное логирование в `src/utils/filter.ts` сейчас жёстко включено (`const debug = true`), поэтому контент-скрипт выдаёт подробный вывод в консоль. Сводный лог `FILTERED` выводится безусловно — он находится вне ограждения `debug` — поэтому он появляется, даже если флаг выключен.

## Разработка

### Предварительные требования

- **Node.js 20** (версия, используемая в CI).
- npm (репозиторий поставляется с `package-lock.json`).

### Установка

```bash
npm ci   # postinstall runs `wxt prepare` to generate WXT-managed types (.wxt/)
```

### npm-скрипты

| Скрипт | Команда | Что делает |
|---|---|---|
| `dev` | `wxt` | Запускает dev-сервер WXT для Chrome (цель по умолчанию) с HMR. |
| `dev:firefox` | `wxt -b firefox` | Запускает dev-сервер WXT с целью Firefox. |
| `build` | `wxt build` | Продакшен-сборка для Chrome → `.output/chrome-mv3`. |
| `build:firefox` | `wxt build -b firefox` | Продакшен-сборка для Firefox → `.output/firefox-mv3`. |
| `zip` | `wxt zip` | Собирает и упаковывает расширение Chrome в распространяемый zip в `.output/`. |
| `zip:firefox` | `wxt zip -b firefox` | Собирает и упаковывает zip расширения Firefox в `.output/`. |
| `compile` | `wxt prepare && tsc --noEmit` | Генерирует типы WXT, затем проверяет типы без эмиссии. |
| `lint` | `eslint .` | Линтит весь проект (плоская конфигурация ESLint 9 в `eslint.config.js`). |
| `test` | `tsx test-parser.ts` | Запускает тесты парсера количества просмотров по локалям (`test-parser.ts`), охватывающие разбор просмотров/зрителей и определение эфира на всех 9 поддерживаемых языках. |

> ℹ️ `postinstall` запускает `wxt prepare` автоматически после `npm install` / `npm ci`.

Запускайте `npm test` после изменения чего-либо в `src/utils/locales.ts` или `src/utils/parser.ts` — он проверяет, что реальные строки количеств YouTube (включая формы с NBSP-разделителем и запятой-десятичным разделителем) разбираются в ожидаемые числа для English, 日本語, Español, Português, Deutsch, Français, Русский, 한국어 и 简体中文.

```text
TubeFilter/
├── src/
│   ├── entrypoints/

├── tailwind.config.js

├── README.md
└── RELEASE_GUIDE.md
```

WXT настроен с `srcDir: 'src'` и `modules: ['@wxt-dev/module-react']`. Общая логика импортируется через алиас `@/utils/...`. Манифест объявляет `permissions: ['storage']` и `host_permissions: ['https://www.youtube.com/*']`, с `name: 'TubeFilter'` и описанием "Filter YouTube videos based on views and other metrics." `manifestVersion: 3` в `wxt.config.ts` — единственный источник истины, который принудительно задаёт вывод MV3 для обеих целей.

`tsconfig.json` расширяет сгенерированный WXT `./.wxt/tsconfig.json` и добавляет `jsx: 'react-jsx'`, `allowImportingTsExtensions`, `noUnusedLocals`, `noUnusedParameters` и `noFallthroughCasesInSwitch`.

## Сборка и выпуск

### Результаты сборки

| Цель | Выходной каталог |
|---|---|
| Chrome | `.output/chrome-mv3` |
| Firefox | `.output/firefox-mv3` |

### Zip-артефакты

`wxt zip` упаковывает сборку в `.output/`, используя стандартный шаблон имени zip-файла WXT (`{{name}}-{{version}}-{{browser}}.zip`, где `{{name}}` — это имя `tube-filter` из `package.json`). В `wxt.config.ts` не задан пользовательский шаблон `zipFileName`/`sources`, поэтому имена ниже следуют значениям по умолчанию WXT:

- `tube-filter-<version>-chrome.zip` (например, `tube-filter-1.0.0-chrome.zip`) — подтверждается glob-шаблоном загрузки в рабочем процессе выпуска.
- `tube-filter-<version>-firefox.zip` (например, `tube-filter-1.0.0-firefox.zip`) — подтверждается glob-шаблоном загрузки в рабочем процессе выпуска.
- Zip с исходниками для проверки AMO (значение по умолчанию WXT для цели Firefox, обычно `tube-filter-<version>-sources.zip`). Это имя является значением по умолчанию WXT и не упоминается никаким кодом в репозитории; запустите `npm run zip:firefox`, чтобы подтвердить точное имя файла в вашей среде.

### Рабочий процесс выпуска в GitHub Actions

`.github/workflows/release.yml` (с именем **Release**) срабатывает на событие `release` GitHub с `types: [published]` и имеет `permissions: contents: write`. Задание выполняется на `ubuntu-latest` и:

1. Извлекает код (`actions/checkout@v4`).
2. Настраивает **Node.js 20** с кэшем npm (`actions/setup-node@v4`).
3. Запускает `npm ci` (его `postinstall` запускает `wxt prepare`).
4. Запускает `npm run zip` (Chrome) и `npm run zip:firefox` (Firefox), создавая zip для обоих браузеров.
5. Загружает их как ресурсы выпуска через `softprops/action-gh-release@v2` (с защитой `startsWith(github.ref, 'refs/tags/')`), сопоставляя `.output/tube-filter-*-chrome.zip` и `.output/tube-filter-*-firefox.zip`.

## Участие в разработке

Вклады приветствуются. Прежде чем открывать PR:

1. `npm ci`, чтобы установить зависимости (это также генерирует типы WXT).
2. `npm run lint`, чтобы проверить код с помощью ESLint.
3. `npm run compile`, чтобы проверить типы (`wxt prepare && tsc --noEmit`).
4. `npm test`, чтобы запустить тесты парсера по локалям (особенно после изменения `src/utils/locales.ts` или `src/utils/parser.ts`).
5. Протестируйте свои изменения в обеих целях с помощью `npm run dev` и `npm run dev:firefox`.
